# v2.3.1-001 — a conformance test asserts on host-repository history

**Status:** documented, not repaired. Frozen v2.3.1 semantics are preserved.
**Found:** during the Workflow v2.3.1 extraction into workflow-manager.
**Affects:** `scripts/workflow_integration_test.py`

## What it is

`TestRetiredScopedRemediationLeavesNoLiveSurface` exists to prove the retired
`/accept-scoped-remediation` command left no live surface behind. Most of it
is portable — it globs `.claude/commands/*.md`, checks `workflow_state`
attributes, and lints the operator documents, all of which the Workflow owns.

One test is not:

```python
def test_the_historical_status_note_carries_a_dated_correction(self):
    text = (_repo_root() / "docs/ACTIVE_MILESTONE.md").read_text()
    paragraphs = text.split("\n\n")
    note = next(
        i for i, p in enumerate(paragraphs)
        if p.startswith("**Status note (2026-08-04)**")
    )
    correction = paragraphs[note + 1]
    self.assertTrue(correction.startswith("**Correction (2026-08-26)**"), correction[:80])
```

`docs/ACTIVE_MILESTONE.md` is `workflow_state.FUNCTIONAL_CHECKLIST_PATH` — a
Workflow contract path — but its *content* is the host repository's own
narrative. The two paragraphs this test requires are RepFlow's record of what
was true on 2026-08-04 and the correction added on 2026-08-26. A repository
that has never run the Workflow has neither, and `next()` raises
`StopIteration`.

Two sibling tests in the same class (`test_live_docs_only_name_it_as_retired`,
`test_no_live_doc_routes_an_operator_to_it`) read `CLAUDE.md` and pass
vacuously once the file exists, so the installed `CLAUDE.md` template satisfies
them without asserting anything false.

## Why it is not repaired here

Repairing it means editing frozen v2.3.1 bytes, which this migration must not
do. The alternative — shipping RepFlow's dated paragraphs in the target
template — would write a false historical record into every bootstrapped
repository, which is worse than a known-failing test.

## How it is handled

- The **conformance fixture** (`build_conformance_repo`) carries the frozen
  `docs/ACTIVE_MILESTONE.md` and `CLAUDE.md` as `host-evidence` artifacts. The
  full frozen suite is green there — 1440 tests, matching the upstream
  baseline test-for-test. That is the equivalence evidence.
- A **bootstrapped target** gets clean templates instead. 1439 of 1440 tests
  pass; this one is listed in `migration/portability_exceptions.json`, and
  `tests/test_conformance_suite.py` asserts that the target-repo failure set is
  *exactly* that list — so a second unportable test appearing later fails the
  build rather than being absorbed.

## If a future release repairs it

The portable form is to assert the pairing only when the note is present:

```python
note = next((i for i, p in enumerate(paragraphs)
             if p.startswith("**Status note (2026-08-04)**")), None)
if note is None:
    self.skipTest("no host status note in this repository")
```

That is a change to Workflow source and belongs in a Workflow release, not in
this extraction.
